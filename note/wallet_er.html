ATK Store payment architecture

Wallet-only Checkout with Stripe-funded Balance

โครงสร้างนี้บังคับให้การจ่ายเงินในร้านผ่าน wallet เท่านั้น ส่วน Stripe เป็นตัวกลางเติมเงินเข้า wallet, ยืนยัน funding channel เช่น card หรือ PromptPay และส่ง webhook กลับมาให้ server ปรับ ledger แบบ idempotent

Top-up Flow

Stripe เป็นคนรับเงินและยืนยัน funding channel แต่ server ของเราต้องเป็นคนตัดสินใจ ว่าเมื่อไรจะ credit เข้า wallet; ตอนซื้อสินค้าใช้ wallet balance เท่านั้น

01

Create top-up intent

user เลือกจำนวนเงินและ channel ที่เปิดใช้ ระบบสร้าง wallet_topup_intents เป็น status created

02

Create Stripe Checkout

server สร้าง Checkout Session พร้อม payment_method_types ตาม channel และ metadata: topupIntentId, walletId, userId

03

Customer pays

Stripe รับเงินด้วย channel ที่เลือก เช่น card หรือ PromptPay แล้ว redirect user กลับ app แต่ยังไม่ถือว่า wallet credited

04

Webhook confirms

server verify signature, insert stripe_webhook_events, mark top-up paid แบบ idempotent พร้อมบันทึก confirmed_channel

05

Credit ledger

สร้าง credit ledger entry และ update wallets.balance_available_minor ใน transaction เดียวกัน

Design Rules

01
Money uses integer minor units เก็บเป็นสตางค์ เช่น 100 บาท = 10000 minor units เลี่ยง double precision สำหรับเงิน
02
Ledger is append-only ยอดผิดให้ทำ reversal entry ไม่แก้ row เดิม เพื่อ audit ได้ครบ
03
Webhook is trusted funding confirmation หน้า success ของ Stripe ใช้บอก user ได้ แต่ห้าม credit wallet จาก redirect อย่างเดียว
04
Every mutation is idempotent top-up, wallet order payment, refund ต้องมี idempotency_key หรือ provider event unique key
05
Order payment is wallet-only Stripe ไม่ควรเป็น payment method ของ order โดยตรงใน app flow นี้

Status Model

wallet.status active, suspended, closed
topup.status created, checkout_open, paid, failed, canceled, refunded
ledger.type topup_credit, order_debit, refund_credit, adjustment_credit, adjustment_debit
order_payment.status pending, paid, failed, refunded
funding.channel card, promptpay, or any Stripe-enabled method

Implementation Notes

ส่วนนี้คือข้อเสนอสำหรับ migration รอบ production ไม่ใช่ table ที่มีอยู่ครบแล้วใน repo ตอนนี้

Phase 1: top-up only

  • เพิ่ม wallets, stripe_customers, wallet_topup_intents, wallet_funding_channels
  • เพิ่ม stripe_webhook_events เพื่อกัน event ซ้ำ
  • เติม wallet เฉพาะจาก webhook ที่ verified แล้ว และบันทึก confirmed_channel

Phase 2: pay from wallet

  • เพิ่ม order_payments เป็นชั้นกลางระหว่าง orders กับ ledger โดย method เป็น wallet เท่านั้น
  • ตอน checkout ต้อง lock wallet row หรือใช้ transaction isolation
  • ไม่ให้ balance_available_minor ติดลบ เว้นแต่ตั้งใจทำ credit line

Phase 3: saved card

  • ค่อยเพิ่ม user_payment_methods ถ้าต้องเก็บ payment method สำหรับ quick top-up รอบถัดไป
  • เก็บเฉพาะ Stripe payment_method id, brand, last4, exp ไม่เก็บเลขบัตร
  • ถ้าแค่ top-up ผ่าน Checkout ยังไม่จำเป็นต้องมี table นี้ และยังไม่ใช้จ่าย order โดยตรง

Recommended principle: Stripe owns wallet funding collection and payment method security; ATK Store owns wallet-only checkout, customer balance, ledger audit, and order settlement.
